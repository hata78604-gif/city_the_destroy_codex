# Roblox 破壊サンドボックスゲーム「爆破訓練場（仮）」実装指示書

## 0. この指示書について

- 実装対象: Roblox Studio 用の Luau スクリプト一式
- **出力形式**: Rojo は使わない。Roblox Studio に手動で配置する前提で、`.lua` ファイルを個別に生成すること。各ファイルの冒頭コメントに「配置場所」「Script / LocalScript / ModuleScript の種別」を明記すること
- 最後に `SETUP.md`（Studio への配置手順書。プログラミング初心者でも迷わないレベルの具体度）を必ず生成すること
- すべての破壊判定・スコア計算は**サーバー権威**で行う。クライアントは演出と入力のみ。通信は RemoteEvent / RemoteFunction を使用
- 設定値（爆発半径、スコア、制限時間など）はすべて `Config.lua`（ModuleScript）に集約し、マジックナンバーをコードに直書きしない

---

## 1. ゲームコンセプト

制限時間内に、武器を使って建物を破壊し、スコアを競う PvE 破壊サンドボックス。

**ゲームループ:**
1. ロビー待機（15秒）— マップが自動生成される
2. ラウンド開始（120秒）— プレイヤーは武器で建物と NPC を破壊してスコアを稼ぐ
3. リザルト表示（10秒）— 破壊率・スコアランキング表示
4. マップ全削除 → 再生成 → 1 に戻る

ソロでも複数人でも動作すること。

---

## 2. マップ生成（BuildingGenerator）

- ModuleScript として実装。スクリプトから建物を**プロシージャル生成**する（Studio 手作業のモデルに依存しない）
- 建物 3 棟を生成する:
  - 小屋（1階建て、約 20x20x10 stud）
  - 中型ビル（2階建て、約 30x30x20 stud）
  - 大型ビル（3階建て、約 40x40x30 stud）
- **壁・床・屋根はすべて小ブロックの集合体**として組む。1ブロックは約 4x2x2 stud。これが破壊の最小単位になる
- 壁には窓・ドアの開口部を作る（該当位置のブロックを生成しない）
- 各ブロックは `Anchored = true` で生成。色は砂色系（コンクリート風）でバリエーションを少し付ける
- 各建物のブロックには `CollectionService` タグ `"Destructible"` と、属性 `BuildingId` を付与する
- **総パーツ数は 3,000 個以下**に収めること。生成後に実数をログ出力する
- 地面はベースプレート + 簡単な地形（道路風の Part）でよい

---

## 3. 武器（3種）

武器は Tool として実装。ラウンド開始時に全プレイヤーの Backpack に配布する。

### 3.1 バズーカ（メイン武器）
- クリック / タップで弾を発射。弾は直進する Projectile（サーバー側で生成・移動）
- 着弾で爆発（半径 12 stud）。リロード 2 秒
- 弾速はゆっくりめ（100 stud/s 程度）にして弾が見える楽しさを出す

### 3.2 エアストライク（範囲攻撃）
- 地点をクリックで指定 → 赤いマーカー表示 → 3 秒後に上空から爆弾 5 発が着弾地点周辺（半径 15 stud にランダム散布）に落下
- 各爆弾は半径 10 stud の爆発。クールダウン 20 秒

### 3.3 リモート爆弾（設置型）
- クリックで足元付近に爆弾を設置（最大 3 個まで）
- 再度アクションボタンで**全弾同時起爆**（半径 15 stud の大爆発）
- 起爆後クールダウン 5 秒

**共通仕様:**
- 武器切替: PC はキーボード 1 / 2 / 3、モバイルは画面ボタン。**モバイル対応必須**（息子がタブレットでプレイする想定）
- 爆発処理は `Explosion` インスタンスを直接使わず、**自前の爆発関数**で実装する（後述の破壊処理・スコア処理と統合するため）。ただし演出用に `Explosion` の見た目 or ParticleEmitter は使ってよい

---

## 4. 破壊処理（DestructionManager）

爆発発生時の処理（サーバー）:

1. 爆発中心から半径内の `"Destructible"` タグ付きブロックを `GetPartBoundsInRadius` 系で取得
2. 対象ブロックを `Anchored = false` にし、爆発中心から外向きの力（`ApplyImpulse`）を加えて吹き飛ばす。力の大きさは中心からの距離で減衰させる
3. 吹き飛んだブロックはタグを `"Debris"` に変更し、スコアを加算
4. **瓦礫のライフサイクル**: unanchor から 8 秒後に 1 秒かけて透明化フェード → `Destroy()`
5. **負荷上限**: 同時に unanchored 状態のパーツは最大 500 個。超えたら古い瓦礫から即時 Destroy する
6. 瓦礫は `SetNetworkOwner(nil)` でサーバー物理に固定する
7. CollisionGroup を設定し、**瓦礫同士は衝突しない**ようにする（物理負荷削減。瓦礫はプレイヤー・地面・建物とだけ衝突）

---

## 5. NPC（NPCManager）

- **Humanoid を使わない軽量ダミー**として実装（頭・胴体・手足のパーツを Weld で結合した人形。緑色）
- 挙動: マップ内をランダムな地点へゆっくり移動し続けるだけの Wander AI（CFrame 補間 or AlignPosition。経路探索は不要）
- 爆風を受けたら: Weld を一部破壊してラグドール化し、爆発の力で吹き飛ぶ。10 秒後に消滅
- 撃破時にスコア加算 + 撃破エフェクト（パーティクル）
- マップ上に**常時 10 体を維持**（消滅したら数秒後に別地点にスポーン）

---

## 6. スコアリング

| 対象 | 点数 |
|---|---|
| ブロック 1 個破壊 | 10 点 |
| NPC 1 体撃破 | 100 点 |
| 建物 1 棟を 90% 以上破壊（全壊ボーナス、棟ごとに 1 回） | 500 点 |

- 破壊率 = その建物の破壊済みブロック数 ÷ 生成時の総ブロック数
- スコアはプレイヤーごとに集計（誰の爆発かを追跡する）
- leaderstats に反映して Roblox 標準のプレイヤーリストにも表示する

---

## 7. 演出（EffectsClient）

爽快感の要。手を抜かないこと。すべてクライアント側で再生（サーバーから RemoteEvent で通知）。

- **爆発**: 火花 + 煙の ParticleEmitter、閃光（短時間の PointLight）、爆発音（大きさ違いを 2〜3 種、`SoundService` 経由。Roblox 提供の無料サウンド ID を使用）
- **カメラシェイク**: 爆発との距離に応じて減衰する揺れ。自前実装でよい（簡易なオフセット振動で可）
- **建物崩壊時**: 粉塵（大きめの煙パーティクル）
- **エアストライク**: 着弾予告マーカー（赤い円）、落下する爆弾に飛翔音
- **ヒット表示**: スコア加算時に画面のスコアがポップする程度でよい（ダメージ数字の飛び出しまでは不要）

---

## 8. UI（UIController + StarterGui）

- **HUD**: 残り時間（画面上部中央）、自分のスコア（右上）、武器スロット 3 つ（画面下部。現在の武器をハイライト、クールダウン中は暗転 + 残秒数）
- **モバイル用**: 発射ボタン・武器切替ボタンを画面右下に配置
- **リザルト画面**: ラウンド終了時に全画面表示。順位・スコア・建物破壊率。10 秒後自動で閉じる
- **ラウンド状態表示**: 「まもなく開始…」「破壊せよ！」「終了！」などの中央テロップ
- UI は Frame + TextLabel のシンプル構成でよいが、フォントは太め、色は視認性重視

---

## 9. ファイル構成

```
ServerScriptService/
  GameManager.server.lua        -- ラウンド進行の司令塔
  Modules/
    Config.lua                  -- 全設定値（ModuleScript）※ReplicatedStorageでも可
    BuildingGenerator.lua       -- 建物生成
    DestructionManager.lua      -- 爆発・破壊・瓦礫管理
    NPCManager.lua              -- NPC生成・AI・ラグドール
    WeaponServer.lua            -- 武器のサーバー側処理・スコア集計
ReplicatedStorage/
  Remotes/                      -- RemoteEvent置き場（スクリプトで自動生成でも可）
  SharedConfig.lua              -- クライアントも参照する設定
StarterPlayer/
  StarterPlayerScripts/
    WeaponClient.client.lua     -- 入力処理・照準・武器切替
    EffectsClient.client.lua    -- 爆発演出・カメラシェイク
    UIController.client.lua     -- HUD・リザルト
```

構成は改善提案があれば変えてよいが、**役割ごとの分割**と**配置場所の明記**は守ること。

## 10. 実装順序（この順で作り、各フェーズ完了時に動作確認ポイントを示すこと）

1. **Phase 1**: Config + BuildingGenerator + バズーカ + 破壊処理 → 「建物を撃って崩せる」
2. **Phase 2**: GameManager（ラウンドループ）+ スコアリング + leaderstats
3. **Phase 3**: NPC（Wander + ラグドール）
4. **Phase 4**: エアストライク + リモート爆弾 + UI 一式
5. **Phase 5**: 演出強化（カメラシェイク・音・粉塵）+ 瓦礫最適化の仕上げ

## 11. 受け入れ基準

- [ ] Studio のソロテストプレイでラウンドが 1 周する（生成→破壊→リザルト→再生成）
- [ ] 大型ビルにエアストライクを撃ち込んでも明らかなカクつきがない（瓦礫上限が機能している）
- [ ] 3 武器すべてが PC・モバイル両方の操作で使える
- [ ] スコアが正しく加算され、全壊ボーナスが棟ごとに 1 回だけ入る
- [ ] エラーが Output に出ない（テストプレイ 3 分間）

---

## 12. 制約・注意事項

- Luau の型注釈は任意（可読性優先でよい）
- 無料アセット ID（音）が無効だった場合に備え、音が鳴らなくてもエラーにならないようにする
- スクリプトのコメントは日本語で書くこと（メンテするのは初心者に近い開発者）
- 既知の Roblox 仕様変更（Deprecated API）を使わない。`BodyVelocity` 等の旧 BodyMover 禁止、`ApplyImpulse` / AlignPosition 等の新 API を使う
- 1 ファイルが 400 行を超えそうなら分割を検討すること
