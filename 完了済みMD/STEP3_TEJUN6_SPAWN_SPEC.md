## 1. 解決したい問題

現状 `pickSpawnPoint()` は道路交点25点から条件を満たす点を返すが、**同じ点が複数回選ばれうる**
(手順5の調査 1-4 で確認済み。ジッターは存在しない)。結果、以下が起きる。

| # | 症状 | 深刻度 |
|---|---|---|
| A | パトカー2台が同じ交差点に湧き、車体が完全に重なる | **高**。1台にしか見えず、経路も同一になるため2台が最後まで重なったまま走る |
| B | 警官2人が同じ交差点に湧き、完全に重なる | 中。**見た目の問題のみ**(下記参照) |

### B が「見た目の問題のみ」である理由 ★重要

重なった警官が爆発1発でまとめて倒れるのは**正しい挙動**であり、修正対象ではない。
爆発は `EnemyManager.OnExplosion` 経由で範囲内の敵すべてに届く設計で、これは実機確認済み。
まとめて倒せることはクリック回数の削減につながるため、**維持すべき利点**である。

したがって B の対策は「爆風の範囲内に収めたまま、目で2人と分かる程度に散らす」ことが目的。
**散らしすぎて1発で複数倒せなくなると、手数が増えて改悪になる。** 数値を大きくしないこと。

## 3. Config への追加

`Config.Threat.Spawn` に以下を追加する。**既存キーは変更しない。**

| キー | 値 | 意味 |
|---|---|---|
| `Jitter` | `6` | 交差点中心から散らす最大距離(stud)。**この値を大きくしないこと**(§1 の理由) |

### `Jitter = 6` の根拠(変更する際は必ず読むこと)

- 道路幅は 16 stud(中心から ±8)。6 なら道路からはみ出さず、建物にめり込まない
- バズーカの爆発半径より十分小さいため、**2人が同じ交差点に湧いても1発でまとめて倒せる状態を保つ**
- 人型の幅より十分大きいため、目で2人と判別できる

**上げてよいのは「まだ重なって見える」場合のみ。8 を上限とする**(道路幅の半分)。

## 4. 実装

### 4-1. パトカー(`Movement == "road"`)── 交差点の重複を避ける

`DeploySquad` の中で、**その1回の派遣に閉じた**使用済み座標の集合を持つ。

```lua
-- DeploySquad の冒頭
local usedPoints = {}   -- key: "x,z" の文字列 / value: true
```

| 種別 | `usedPoints` への書き込み | `usedPoints` の参照 |
|---|---|---|
| `Movement == "road"`(パトカー・将来の戦車) | **する** | する |
| それ以外(警官・将来の兵士) | **しない** | する |

つまり:

- パトカー同士は必ず別の交差点になる
- 警官はパトカーの交差点を避ける(車体との重なり防止)
- **警官同士は同じ交差点を共有してよい**

### なぜ警官同士の共有を許すか ★変更しないこと

編成全体に重複禁止を適用すると、★3(10体)で最後の個体が使える交差点が遠くにしか残らず、
**300stud 離れた場所に湧いて「波」としてまとまらなくなる**。
書き込むのは `road` 個体だけ(★3でも最大4点)なので、25点あるうちの大半は残る。

### 4-2. 候補が尽きたときのフォールバック ★必須

除外の結果、条件を満たす候補が1つも無くなった場合:

1. **`usedPoints` の除外を諦めて**、`MinDistanceFromPlayer` の条件だけで選び直す
2. `warn` を1回出す

```lua
warn("[EnemyManager] 湧き位置の候補が枯渇。重複を許可して配置します")
```

**`MinDistanceFromPlayer` の方を諦めてはいけない。** プレイヤーの目の前に敵が湧くのは、
2台が重なるより明確に悪い体験になる。

湧き自体を中止する(`nil` を返して個体をスキップする)のも禁止。
「1つの条件が満たせないせいで編成が欠ける」事故は、手順2で既に一度踏んでいる。

### 4-3. 警官(`Movement ~= "road"`)── ジッター

選ばれた交差点座標に、水平方向のランダムオフセットを加える。

```lua
local ang = rng:NextNumber(0, math.pi * 2)
local r   = Config.Threat.Spawn.Jitter * rng:NextNumber(0.5, 1.0)
pos = Vector3.new(pos.X + math.cos(ang) * r, pos.Y, pos.Z + math.sin(ang) * r)
```

- **角度は一様ランダム、距離は最大値の 0.5〜1.0 倍**。
  X と Z を独立に振ると中心付近に集まりやすく、重なりが残る
- **Y は触らない。** 接地高さは `spawnEnemy` 側が `etype.SpawnY` で決める仕様(手順2で決定済み)
- 乱数はモジュールスコープの `rng` を使う(`math.random` は使わない。手順5と同じ方針)

### 4-4. パトカーにジッターを適用しない ★重要

`Movement == "road"` の個体には**ジッターを一切かけない。**

理由: 走行AI(§3-4)は「車は縦道路か横道路のどちらかの線上にいる」ことを前提に経路を組み立てる。
X と Z の両方をずらすと、湧いた瞬間だけどちらの線上にも乗っていない状態になる。
`nearestLine` で吸収はされるが、走り出しの1〜2フレームだけ横滑りする絵になる。
交差点の重複禁止(§4-1)で十分に分散されるので、ジッターは不要。

### 4-5. ジッターを適用してはいけない場所 ★事故防止

**ジッターは `DeploySquad` の湧き位置選定の中だけに書くこと。`spawnEnemy` の内部に書かないこと。**

`spawnEnemy` は手順5の `deployFromCar` からも呼ばれており、そこでは
「車の左右のドア横」という意図をもって座標を計算している。
`spawnEnemy` 側でジッターをかけると、この意図した配置が毎回ずれて台無しになる。

## 6. 受け入れ基準

### 分散
- [ ] パトカー2台が**必ず別々の交差点**から湧く(10回ラウンドを回して1度も重ならない)
- [ ] 警官が交差点の中心からずれた位置に湧き、2人が完全に重なることがない
- [ ] 警官がパトカーの車体に重なって湧かない
- [ ] 警官が道路からはみ出して芝生や建物の上に湧かない
- [ ] 警官が地面にめり込んだり浮いたりしていない(Y座標が壊れていない)

### 維持されるべき挙動 ★これが崩れたら改悪
- [ ] **同じ交差点に湧いた警官2人が、バズーカ1発でまとめて倒せる**(散らしすぎていない)
- [ ] 湧いた敵がプレイヤーから `MinDistanceFromPlayer` 以上離れている(目の前に湧かない)
- [ ] 編成の全員が湧く。個体が欠けない

### 既存機能の非破壊
- [ ] 手順5の降車が従来どおり(車の左右のドア横に2人・15秒ごと・強制降車の保険)
- [ ] **降車した警官の位置にジッターがかかっていない**(ドア横のまま。§4-5)
- [ ] 手順4の走行挙動が変わっていない(湧いた直後に横滑りしない)
- [ ] `squadId` の全滅判定が従来どおり(パトカーを倒すまで次の波が来ない)
- [ ] 3武器すべてで従来どおり爆発・破壊・スコア加算が起きる
- [ ] 市民NPCの挙動が従来どおり
- [ ] ラウンドが LOBBY → BATTLE → RESULT を1周する
- [ ] `Config.Threat.Enabled = false` で敵が一切出ない
- [ ] 出力ウィンドウ(サーバー・クライアント両方)に赤いエラーが1つも出ない
- [ ] `[EnemyManager] 湧き位置の候補が枯渇` の warn が**通常のプレイで出ない**(出るなら報告すること)
