# 追加指示書3: 手作り建物テンプレート方式（BuildingTemplates）

## 0. この指示書について

- これは `roblox_destruction_game_spec.md`（本体）、`city_expansion_spec.md`（街並み拡張）、`visual_upgrade_spec.md`（ビジュアル強化）への**追加指示**である。既存方針（サーバー権威、Config集約、日本語コメント、SETUP.md更新）はすべて維持すること
- 目的: ユーザーが **Roblox Studio 上で手作りした建物モデル**を、街生成に組み込めるようにする。プロシージャル生成（既存のテンプレート）と手作りモデルの**併用**を可能にする
- 破壊処理・スコアのロジックは変更しない。**手作り建物もプロシージャル建物と全く同じように壊せて、全壊ボーナスも正しく入る**ことがゴール

---

## 1. 仕組みの概要

```
ReplicatedStorage/
  BuildingTemplates/        ← ユーザーが手作りモデルを置くフォルダ
    House1 (Model)          ← 小ブロックを積んで作った建物
    House2 (Model)
    ...
```

- CityGenerator は建物スロットに配置する際、**「プロシージャル生成」か「テンプレートのクローン」かを選べる**ようにする
- テンプレートをクローンした場合、CityGenerator が以下を**自動で行う**:
  1. モデル内の全 BasePart に `Destructible` タグを付与
  2. `BuildingId` 属性を付与（棟ごとに一意）
  3. `Anchored = true` を強制（作り手の設定ミスをカバー）
  4. ブロック総数を破壊率トラッキングに登録（全壊ボーナス用）
  5. 配置位置への移動（PivotTo）と、道路に向いた回転

---

## 2. Config の設計

`Config.City.Slots` の各スロットに建物の指定方法を追加する。例:

```lua
Slots = {
    { position = ..., building = "procedural" },        -- 既存のプロシージャル生成
    { position = ..., building = "template:House1" },   -- 手作りテンプレート指定
    { position = ..., building = "template:random" },   -- テンプレートからランダム
    { position = ..., building = "random" },            -- プロシージャル+テンプレート全体からランダム
}
```

- `BuildingTemplates` フォルダが存在しない・空の場合、`template:` 指定は警告ログを出して**プロシージャル生成にフォールバック**する（エラーで止めない）
- デフォルトの Slots は全て `"random"` にしておく（テンプレートを置けば自動的に混ざる）

---

## 3. テンプレートの検証（TemplateValidator）

クローン前にテンプレートの内容をチェックし、問題があれば**分かりやすい日本語の警告ログ**を出す:

| チェック項目 | 判定 | 動作 |
|---|---|---|
| Model である | 必須 | 違えばスキップして警告 |
| PrimaryPart が設定済み | 必須 | 未設定なら**最下部のPartを自動でPrimaryPartに設定**して警告（止めない） |
| BasePart の数 | 10個以上 | 少なすぎる場合「壊す部分が少ない」警告のみ |
| 1個あたりのPartサイズ | 最大辺 8 stud 以下推奨 | 超えるPartがあれば「大きなパーツは崩れる楽しさが減ります」警告のみ |
| Script/LocalScript を含まない | 必須 | 含んでいたら**そのスクリプトだけ削除**して警告（Toolbox由来の不正スクリプト対策） |
| Humanoid 等の余計なインスタンス | - | あれば削除 |
| モデル全体のパーツ数 | - | ログに出力（総パーツ数6,000の管理用） |

- 検証結果は起動時にまとめてログ出力: `[TemplateValidator] House1: OK (パーツ 312個)` / `[TemplateValidator] House2: 警告あり(...)` の形式

---

## 4. 配置時の挙動

- テンプレートの寸法（`Model:GetExtentsSize()`）を取得し、スロットの区画サイズに収まらない場合は警告を出して**そのまま配置**する（自動縮小はしない。スケール変更は破壊の粒度が崩れるため）
- 接地: PrimaryPart（土台）の底面が Terrain/地面の高さに合うように Y 座標を計算して配置する（半埋まり・浮きを防ぐ）
- 回転: スロットが面する道路の方向に正面（PrimaryPart の LookVector 基準）を向ける。ランダム90度回転はしない
- クローン後のモデルは既存の `Map` フォルダ配下に置き、ラウンド終了時の一括削除に含める
- **総パーツ数上限6,000のチェックにテンプレート分も含める**。超過したら以降のスロットをプロシージャル小屋（最小サイズ）に切り替えて警告

---

## 5. スコア・破壊との整合

- 手作り建物のブロックも 1個10点（既存と同じ）
- 全壊ボーナス: テンプレート建物も BuildingId ごとに総ブロック数を登録するので、既存の90%判定がそのまま機能すること
- 瓦礫化・上限500個・衝突グループの挙動も既存のまま適用されること（タグさえ付けば DestructionManager 側は変更不要のはず。**変更不要であることを確認し、必要な場合のみ最小限の修正**にとどめる)

---

## 6. SETUP.md への追記事項（重要・初心者向けに丁寧に）

「自分で作った建物をゲームに登場させる方法」の章を追加する。内容:

1. **建物の作り方のルール**:
   - パーツは小さめ（目安 4x2x2、最大でも 8 stud 以下）で積み上げる
   - 大きな1枚壁で作ると「壁ごとドン」と飛ぶだけになって面白くない、という理由の説明
   - 完成したら全パーツを選択して右クリック →「グループ化（Model）」
   - Model を選んでプロパティの `PrimaryPart` に**土台のPart**を設定する手順
2. **登録手順**: Model を `ReplicatedStorage/BuildingTemplates` にドラッグして名前を付ける（House1 など）
3. **確認方法**: テストプレイして出力に `[TemplateValidator] House1: OK` が出ること、街に自分の建物が混ざって生成されること
4. **よくある失敗**: PrimaryPart 未設定（自動補正される旨）、パーツが大きすぎる警告の意味、建物が大きすぎて区画からはみ出す場合の対処（区画サイズは Config.City.Slots で調整可能）
5. 親子で建物を作って登録する遊び方の提案（1〜2行でよい）

## 7. 受け入れ基準

- [ ] `BuildingTemplates` に置いた手作りモデル（小ブロック構成）が街に混ざって生成される
- [ ] 手作り建物がバズーカで壊せて、ブロック10点・全壊ボーナス500点が正しく入る
- [ ] PrimaryPart 未設定のモデルでもエラーで止まらない（自動補正+警告）
- [ ] Script入りモデルを置いてもスクリプトが除去される
- [ ] `BuildingTemplates` が空でも従来どおりプロシージャル生成で動く
- [ ] 総パーツ数6,000の上限管理にテンプレート分が含まれる
- [ ] ラウンド再生成で手作り建物も正しく消えて再配置される
