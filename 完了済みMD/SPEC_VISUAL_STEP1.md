## 2. A-5: カラーパレットを現実寄りにする

### 2-1. 狙い

現在のパレットは彩度が高く「おもちゃの街」に見える。
現実の街並みは **壁が明るく低彩度(白・ベージュ・薄いグレー・くすんだレンガ)、
屋根が濃いグレー〜黒** という強いコントラストを持つ。この対比が「町らしさ」の主要因。

**屋根の色を全パレットで濃いグレー系に寄せることが、この項目で最も効果が大きい。**

### 2-2. 変更内容

`Config.Visual.BuildingPalettes` を以下の5種に差し替える(現在3種)。
既存のキー構造(`material` / `wallColors`(3色) / `frameColor` / `roofMaterial` / `roofColor`)は**変更しない**。

| # | name | material | wallColors(3色の方向性) | frameColor | roofMaterial | roofColor |
|---|---|---|---|---|---|---|
| 1 | 白い家 | Concrete | 白〜オフホワイト(235前後の無彩色寄り) | 濃いグレー | Slate | 濃いグレー(45,48,52 前後) |
| 2 | ベージュの家 | Sandstone | ベージュ〜クリーム(くすませる) | 茶系 | Slate | こげ茶〜黒(50,45,40 前後) |
| 3 | レンガの店 | Brick | くすんだレンガ色(彩度を現在より下げる) | オフホワイト | Slate | 濃いグレー |
| 4 | コンクリビル | Concrete | 明度違いのグレー3色 | 濃いグレー | Concrete | 濃いグレー |
| 5 | ガラスビル | Metal | 青みがかった薄いグレー3色 | 濃紺 | Metal | 濃いグレー |

**具体的なRGB値は実装者が上記の方向性に沿って決めてよい。**
ただし以下を守ること。

- **壁色は彩度を低く**保つ(原色・鮮やかな色を使わない)
- **屋根色は全パレットで明度を低く**(RGB各値が概ね60以下)
- 同一パレット内の `wallColors` 3色は**近い色**にする(同じ通りの家々が微妙に違う程度)

### 2-3. あわせて確認すること

`Config.Block.ColorJitter`(現在16)は「同じ壁でもブロックごとに色が微妙にずれる」効果で、
経年劣化のような質感を出している。**変更しない**が、パレットを地味にした結果
ノイズが目立ちすぎるようなら、計画報告で下げる提案をしてよい。

## 3. A-2: 三角屋根(切妻屋根)

### 3-1. 狙い

参考にした人気ゲームの街並みを分析した結果、**建物の形状は全て単純な箱**であり、
リアルに見せている最大の要因が**三角屋根**だった。現在は全建物が平らな屋根(`buildSlab`)。

### 3-2. 適用ルール

**階数によって屋根の種類を分ける。**

| 条件 | 屋根 |
|---|---|
| `storeys <= 2` | **切妻屋根(三角)** ← 新規 |
| `storeys >= 3` | 陸屋根(平ら) ← 現状のまま |

現実の街でも低層住宅は三角屋根、高層ビルは陸屋根であり、この分岐が自然。
グリッドモードで選ばれるテンプレートは `小屋`(1階) / `店舗`(1階) / `高層ビル`(8階)の3種なので、
**小屋と店舗が三角屋根、高層ビルは平らのまま**になる。

### 3-3. 形状の作り方

`WedgePart` を2枚、斜面を向かい合わせに配置して三角柱を作る。

- **棟(ridge)の向き**: 建物の**長辺方向**に走らせる(短辺側から見て三角形が見える)
- **屋根の高さ**: `Config.Visual.Roof.GableHeight`(新規Config。既定 6)
- **軒(overhang)**: 壁の外側へ `Config.Visual.Roof.Overhang`(新規Config。既定 2)stud はみ出させる。
  **軒はリアルさへの寄与が大きいので省略しないこと**(壁とツライチだと箱に三角を載せただけに見える)

### 3-4. 分割すること(重要)

**1枚のWedgePartで屋根全体を覆ってはいけない。**

このゲームの根幹は「小さいブロックの集合が爆発でバラバラに吹き飛ぶ」ことであり、
巨大な1枚パーツは「屋根ごとドンと1個飛ぶ」という最も避けたい壊れ方になる
(`SETUP.md` 7-1 に同じ趣旨のルールが手作り建物向けに明記されている)。

**棟方向に `Config.Block.Size.X`(=8)単位で分割する。**
例: 棟方向の長さが24なら、片側3枚 × 2面 = 6枚のWedgePart。

### 3-5. 破壊まわりの扱い

屋根のWedgePartは**壁ブロックと完全に同じ扱い**にする。

- `Destructible` タグを付ける
- `BuildingId` 属性をその建物のIDにする(全壊ボーナスの判定に含める)
- スコアは既存の `Config.Score.Block`(10点)がそのまま適用される

**新しいスコア種別・新しいタグを作らないこと。** 既存の破壊経路にそのまま乗せる。

### 3-6. 追加するConfig

`Config.Visual.Roof` を新設する。

| キー | 既定値 | 意味 |
|---|---|---|
| `GableEnabled` | `true` | 切妻屋根のON/OFF。falseで全建物が従来の平らな屋根に戻る |
| `GableMaxStoreys` | `2` | この階数以下の建物に切妻屋根を付ける |
| `GableHeight` | `6` | 棟の高さ(stud) |
| `Overhang` | `2` | 軒の出(stud) |

**全て実機で振る値である。**(`CURRENT_SPEC.md` §12-1 の方針どおり、
振らないと決めた設計判断はConfigキーにしない)

## 4. A-3 / A-4: グリッドモードで石垣と街小物を有効化

### 4-1. 現状

`buildStoneWalls`(石垣)と `buildProps`(街灯12本/車6台/木9本/ベンチ2脚)は
**関数として存在するが、グリッドモードでは呼ばれていない**(`CURRENT_SPEC.md` §7)。

従来モードの実装は `Config.City.Slots`(13棟)を前提にしているため、
**そのまま呼んでも正しく配置されない。**グリッドの座標系に合わせた実装が必要。

### 4-2. 方針: 従来モードのコードは触らない

**従来モード(`USE_GRID_MODE=false`)の `buildStoneWalls` / `buildProps` は一切変更しない。**
グリッド用の新しい関数(`buildGridStoneWalls` / `buildGridProps`)を追加する。

理由: 従来モードは凍結中だが「いつでも切り替えられる」状態を維持する方針であり
(`CURRENT_SPEC.md` §6-1)、共通化のために既存関数を書き換えると、
検証されていない従来モードが壊れても気付けない。

**パーツ生成のヘルパー(色・材質・タグ付けなど)に再利用できるものがあれば、それは共用してよい。**

### 4-3. 石垣の配置(`buildGridStoneWalls`)

**各街区(タイル)の外周に沿って石垣を並べる。**

- 位置: タイル中心から `±(GRID_BLOCKSPAN / 2)`(= ±54)の正方形の辺上
- 間隔: `Config.Visual.StoneWall.Spacing`(現在4)
- **建物と重なる位置はスキップする**。配置済み建物のフットプリント(+マージン)に
  入る位置には石垣を置かない
  - `CityGenerator` には既に `makeSkipFn` という「特定位置を飛ばす」パターンがあるので、
    同じ考え方を使えるか検討すること
  - 建物のフットプリントは、スロット位置と実際に選ばれたテンプレートの寸法・向きから求まる。
    建物生成時にこの情報を集めておく必要がある
- 破壊: 従来モードと同じく **`Destructible` タグを付け、破壊で10点入る**
- **`BuildingId` 属性は付けない**。石垣が建物の全壊判定や建物破壊率に混ざると
  リザルトの数値の意味が変わってしまうため

> **確認事項**: 従来モードの `buildStoneWalls` が `BuildingId` を付けていないことを
> 実装前にコードで確認すること。付けている場合は計画報告で報告すること。

### 4-4. 街小物の配置(`buildGridProps`)

**道路網と街区の空きスペースを基準に配置する。**(`Config.City.Slots` は使わない)

| 小物 | 配置場所 | 数の決め方 |
|---|---|---|
| 街灯 | 歩道の上。各道路に沿って等間隔 | `Config.Visual.Props.LampSpacing` 間隔 |
| 駐車車両 | 車道の路肩(車道の端寄り)。向きは道路に沿わせる | 道路1本あたり `CarsPerRoad` 台 |
| 木 | **各街区の中央の空きスペース** | 街区1つあたり `TreesPerBlock` 本 |
| ベンチ | 歩道の上。交差点付近 | 街区1つあたり `BenchesPerBlock` 脚 |

**木の配置場所について**: グリッドモードでは建物が街区の4辺に並ぶため、
**各街区の中央(108×108のうち内側)が完全な空きスペースになっている。**
ここに木を植えると、空白が「意図した公園」に見えるようになる。この効果は大きい。

- 全ての小物は `Anchored = true`、既存どおり `CityProp` タグを付ける
- **`Destructible` タグは付けない**(従来モードと同じ。爆発しても壊れない)
  - 破壊可能にすると建物破壊率とスコアの意味が変わるため、この指示書では変更しない。
    将来の検討事項として `CURRENT_SPEC.md` に記載する(§7)
- 車両は既存の敵パトカーと**見た目で紛らわしくならない色**にする
  (プレイヤーが「敵か置物か」で迷うと操作の妨げになる)

### 4-5. 追加するConfig

`Config.Visual.Props` を新設する。

| キー | 既定値 | 意味 |
|---|---|---|
| `Enabled` | `true` | 街小物全体のON/OFF |
| `LampSpacing` | `62` | 街灯の間隔(stud) |
| `CarsPerRoad` | `3` | 道路1本あたりの駐車車両の台数 |
| `TreesPerBlock` | `5` | 街区1つあたりの木の本数 |
| `BenchesPerBlock` | `1` | 街区1つあたりのベンチの数 |

`Config.Visual.StoneWall.Enabled` は既存キーをそのまま使う。
**あわせて、`StoneWall` に付いている「グリッドモードでは未使用」というコメントを削除すること。**

### 4-6. 生成順序と予算チェック

`CityGenerator.Generate()` のグリッド分岐に、以下の順で追加する。

```
1. buildRoadGrid(map)              ← 既存
2. 建物の生成ループ                  ← 既存(配置済みフットプリントを記録するよう変更)
3. buildGridStoneWalls(map, ...)   ← 新規
4. buildGridProps(map, ...)        ← 新規
```

- 3・4 でも `overBudget()` によるチェックを行い、超過したら安全に打ち切る
- 既存の完了ログ(`建物ブロック ○○ / 石垣 ○○ / 道路・小物 ○○ / 合計 ○○`)が
  **正しい内訳を表示するようにする**(現在グリッドモードでは石垣・小物が常に0のはず)

## 5. EnemyManager への影響(見落とし注意)

**★2のスナイパーは屋上に出現する**(`CURRENT_SPEC.md` §16-4)。
`findRooftopCandidates` は `BuildingId` を持つパーツの最高部(`topY`)を建物ごとに1つ選び、
そこにスナイパーを立たせている。

**三角屋根を追加すると、その建物の最高部が「斜面」になる。**
斜面の頂点にスナイパーが立つと、めり込む・浮く・滑るといった見た目の破綻が起きる。

### 対処

**切妻屋根を持つ建物を、屋上候補から除外する。**

- 建物のModelに属性 `HasGableRoof = true` を付ける(`CityGenerator` 側)
- `findRooftopCandidates` は、この属性が立っている `BuildingId` をスキップする

これにより候補は陸屋根の建物(=`高層ビル`)に限定される。
**低い小屋よりも高層ビルの屋上にスナイパーがいるほうが設計としても自然**なので、
この変更は副作用ではなく改善である。

> **注意**: 候補がゼロになるケース(高層ビルが1棟も建たなかった、全て破壊された等)に
> 既存コードがどう対応しているかを確認し、必要なら地上フォールバックが働くことを確かめること。
> **`EnemyManager` の変更はこの1点のみ。**他のロジックには触れないこと。

## 8. 受け入れ基準

実装完了の報告前に、`roblox-playtest` スキルで実際にゲームを起動して以下を確認すること。

### 見た目

- [ ] 建物の壁が地味な色(白・ベージュ・くすんだレンガ・グレー)になっている
- [ ] **屋根が濃いグレー〜黒**で、壁との明暗差がはっきり出ている
- [ ] 小屋・店舗に三角屋根が付き、**壁より少し外にはみ出している**(軒)
- [ ] 高層ビルの屋根は平らなまま
- [ ] 各街区の外周に石垣が並び、**建物の位置では途切れている**(建物を貫通していない)
- [ ] 歩道に街灯が等間隔で立っている
- [ ] 車道の路肩に車が停まっており、**敵のパトカーと見分けがつく**
- [ ] 各街区の中央に木が植わっている(空白が公園に見える)

### 破壊

- [ ] 三角屋根をバズーカで撃つと、**複数のパーツに分かれて吹き飛ぶ**(1枚でドンと飛ばない)
- [ ] 屋根の破壊で10点入る
- [ ] 石垣を壊すと10点入る
- [ ] **街灯・車・木・ベンチは爆発しても壊れない**
- [ ] 全壊ボーナス(+500点)が1棟につき1回だけ入る(屋根を足しても二重に入らない)
- [ ] リザルトの建物破壊率が、石垣・小物の影響で不自然な値になっていない

### 敵

- [ ] ★2に到達してスナイパーが出現したとき、**陸屋根の建物(高層ビル)の上に立っている**
- [ ] 三角屋根の上にスナイパーが出現しない
- [ ] 屋上候補がゼロの状況でもエラーにならない

### 性能・安定性

- [ ] 出力ログの内訳が正しい(`建物ブロック ○○ / 石垣 ○○ / 道路・小物 ○○ / 合計 ○○`)
- [ ] 合計パーツ数が `Config.Performance.MaxTotalParts` を超えない
- [ ] ラウンド終了→再生成で、石垣・小物・屋根が残らず消える
- [ ] Outputに新しいエラー・警告が出ない(3分間プレイ)
- [ ] `Config.Visual.Roof.GableEnabled = false` で従来の平らな屋根に戻る
